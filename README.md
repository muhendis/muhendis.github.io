# muhendis.github.io

Personal site and blog of **Engin Bozaba** — Expert AI Engineer at Vodafone,
AWS Certified Solutions Architect.

Live at **<https://muhendis.github.io>**. Available in English (`/en/`) and
Turkish (`/tr/`).

Hand-written HTML, CSS and vanilla JavaScript. **No build step, no framework,
no runtime dependencies** beyond one vendored Markdown parser.

---

## Running it locally

```bash
python3 -m http.server 8000
# then open http://localhost:8000
```

**Do not open the files with `file://`.** The site uses root-absolute paths
(`/assets/…`, `/en/…`) which resolve to your filesystem root under `file://`,
and `fetch()` is blocked by CORS for file origins, so no blog post will load.
This is the single most common "why is the site broken" cause here.

---

## The `.nojekyll` file — do not delete it

GitHub Pages runs Jekyll by default. Jekyll treats `.md` files as *source to
compile*, not assets to serve — so without `.nojekyll`, every blog post returns
**404 in production while working perfectly on localhost**.

The empty `.nojekyll` at the repo root disables Jekyll so the tree is served
verbatim. It is checked three ways: a CI step asserts git tracks it,
`validate_site.py` asserts it exists, and `blog-post.js` sniffs for an HTML
doctype in a fetched `.md` and reports the cause if Jekyll is on.

```bash
git ls-files | grep -c nojekyll   # must print 1
```

## Adding a blog post

1. **Write the Markdown** in `en/blog/posts/<slug>.md` (or `tr/…`).
   - Start the body at `##`. **No `# H1`** — the `<h1>` is rendered from the
     `title` in `posts.json` so the heading, `<title>` and Open Graph tags
     cannot drift apart.
   - No YAML front matter. All metadata lives in `posts.json`.
   - Copy `_template.md` as a starting point (files beginning with `_` are
     ignored by the indexer and by CI).

2. **Index it** in the same folder's `posts.json`:

   ```json
   {
     "slug": "my-post",            // must equal the filename without .md
     "title": "My post",
     "date": "2026-09-01",         // YYYY-MM-DD
     "summary": "One sentence for the index and link previews.",
     "tags": ["mlops"],
     "readingMinutes": 6,
     "translationSlug": null,      // the other language's slug, or null
     "draft": false
   }
   ```

3. **If you translate it**, add the other `.md` and its entry, then set
   `translationSlug` on **both** entries pointing at each other. CI checks
   this symmetry — it is the easiest field to forget.

4. **Add the URL to `sitemap.xml`.** Blog index links are generated by JS, so
   the sitemap is the only reliable way crawlers discover posts.

5. Check locally, then `python3 .github/scripts/validate_site.py`, then push.

`"draft": true` hides a post from the index and blocks it from rendering, but
**the file is still public in the repo**. It is a convenience, not privacy.

## Architecture notes

### Why posts render client-side

Posts are fetched as `.md` and rendered in the browser by
[marked](https://github.com/markedjs/marked). Metadata comes from `posts.json`
so the index page needs exactly **one** request rather than one per post.

**The tradeoff, stated plainly:** individual post URLs use a query string
(`post.html?slug=…`) and their content is not in the initial HTML. Google
renders JavaScript and will index them, but **social scrapers do not** — a post
link shared on LinkedIn or Slack shows the generic site card, not the post
title. Accepted deliberately to keep the site build-free.

### Bilingual structure

`/en/` and `/tr/` are real directories with real files — better for search
engines than a JavaScript translation dictionary. Turkish pages deliberately
keep **English filenames** (`publications.html`, not `yayinlar.html`) so the
language switcher is a one-line path swap instead of a lookup table that would
need maintaining.

The switcher is a plain `<a>` with a hardcoded `href` on all pages except
`post.html`, so it works with JavaScript disabled. On `post.html` it is wired at
runtime from `translationSlug`; when a post has no translation the control is
disabled rather than silently sending the reader to the other language's index.

### Shared markup

Header and footer are duplicated across all 12 HTML files — the unavoidable
cost of no build step. They are wrapped in sentinel comments:

```html
<!-- #region shared:header v1 --> … <!-- #endregion shared:header -->
```

`validate_site.py` normalises and compares these blocks across every page, so
drift fails CI instead of going unnoticed. **Edit them in all files or none.**
Nav links are root-absolute (`/en/…`) specifically so the markup is identical
at every directory depth.

### Theming

`prefers-color-scheme` with a manual override stored in `localStorage`. The
saved theme is applied by a small inline script in `<head>` **before** the
stylesheets load — deferring it would flash the light theme on every navigation
in dark mode. The accent colour differs between modes by necessity: the light
teal `#0d7c8a` on the dark background is only ~3.9:1 and fails WCAG AA, so dark
mode uses `#2ed3e4` (~10.4:1).

### Sanitisation

`marked` output is inserted without DOMPurify. Deliberate: content is authored
solely by the repo owner and served same-origin, so the realistic attack
requires repo write access — at which point a sanitiser is moot. **If you ever
accept posts by pull request**, vendor DOMPurify and change one line in
`blog-post.js` to `DOMPurify.sanitize(marked.parse(md))`.

## Layout

```
.nojekyll              disables Jekyll — load-bearing
index.html             bilingual landing page
404.html               must live at the root
assets/css/            tokens → base → layout → components
assets/js/             site.js, blog-index.js, blog-post.js
assets/js/vendor/      marked.umd.js + its MIT licence
en/, tr/               one directory per language
  blog/posts/*.md      post bodies
  blog/posts.json      post index (source of truth for metadata)
.github/scripts/       validate_site.py
```

## Custom domain

No `CNAME` file is committed. Adding one for a domain whose DNS is not yet
pointed at GitHub Pages **takes the site offline**. Add it only after the DNS
`A`/`ALIAS` records resolve.
